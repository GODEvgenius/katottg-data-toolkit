# Підготовка даних КАТОТТГ

Відкрийте `prepare_data.html` у браузері. Усі бібліотеки містяться в `vendor`,
тому конвертація Word / Excel працює без підключення до інтернету та без сервера.
Зберігайте HTML, `prepare_data_core.js` і папку `vendor` разом.

1. Додайте один або кілька наказів у друге поле. Підтримуються Word `.docx`,
   Excel `.xlsx` та `.xls`, у тому числі змішані набори. Повторний вибір додає
   файли до списку; кнопка `×` видаляє файл. Старі Word `.doc` спочатку
   збережіть у форматі `.docx`.
   Файли можна додавати до будь-якого з двох полів: тип кожної таблиці
   (кодифікатор або наказ зі статусами) визначається за її вмістом.
2. За потреби додайте кодифікатор у перше поле. Він має колонки першого,
   другого, третього та четвертого рівнів, категорії та назви. Без кодифікатора
   результат містить лише території з наказів; відсутні коди батьків не вигадуються.
3. Натисніть «Об'єднати та підготувати JSON / XLSX». Звіт показує знайдені
   таблиці / аркуші, номери визначених колонок і пропущені рядки.
4. Завантажте `data.json`, `katottg_merged.xlsx` або повний ZIP.

Word: читаються всі таблиці, враховуються горизонтальні й вертикальні
об'єднання клітинок, багаторядкові заголовки та продовження таблиць із
нумерованими колонками. Excel: читаються всі аркуші, зокрема коли перший
аркуш є супровідним. Таблиці без потрібних колонок не імпортуються;
якщо у файлі взагалі немає потрібних записів, обробка зупиняється з помилкою.

Повтори визначаються за повним кодом КАТОТТГ, статусом, датами та
функціонуванням систем. Різні періоди залишаються в історії; джерела
повторних записів зберігаються. Дати в Excel експортуються як текст
`ДД.ММ.РРРР`, коди КАТОТТГ — як текст.

Excel містить чотири аркуші:

- «Дані КАТОТТГ»: ті самі поточні дані, що й у JSON, у плоскому вигляді.
- «Об’єднані накази»: усі унікальні імпортовані статуси та їхні джерела.
- «Історія статусів»: історія кожної території, включно з переходами до контролю України.
- «Джерела та колонки»: звіт імпорту.

Для повторного імпорту згенерованого Excel автоматично використовується
аркуш «Об’єднані накази», щоб не змішувати вихідні записи із похідними статусами.

Модуль геоданих використовує `data.json`, навіть якщо завантажено лише Excel.
Новий результат автоматично прив'язується до геомодуля. Після зміни вхідних
файлів або прив'язки іншого JSON геофайли потрібно обробити знову.
Повний ZIP включає згенерований Excel поряд із JSON та геоданими.

Статуси регіонів, районів і громад розраховуються за населеними пунктами
рівня 4 (у містах зі спеціальним статусом — за районами міста).
Підсумок містить точні кількості для кожної категорії й одну з трьох груп:
повний контроль, змішані або повністю ТОТ / бойові дії.
Вихідний статус батьківського запису зберігається в `source_status`,
а історія наказів залишається окремою від розрахованого підсумку.

## Перевірка

`tests/prepare_data.test.cjs` запускається через Node з Playwright на `NODE_PATH`.
На Windows за замовчуванням використовується Chrome; інший шлях можна
вказати в `BROWSER_PATH`. Перевірка використовує три вихідні документи з
`internal files`, завантаження JSON / XLSX / ZIP, змішані формати, історію,
ієрархію та геоприв'язку. Мережеві запити у браузері блокуються під час тесту.

`tests/status_summary.test.cjs` і `tests/registry.test.cjs` запускаються
через Node без браузера на вигаданих тестових записах. Вони перевіряють підсумки,
конвертор, групи фільтрів, переходи, відновлення адреси, кольори карти та CSV.

`tests/converter_core.test.cjs` перевіряє визначення таблиць, продовження,
точне зіставлення кодів, історію та повторний імпорт згенерованого Excel
на вигаданих записах. Основні перевірки (`npm test` у корені проєкту)
не потребують вихідних документів або наборів даних.

Публічний репозиторій містить лише програму та документацію. Власні вхідні
документи й результати в `data_files/` не додаються до Git.
